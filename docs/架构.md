## 1. 总览

```text
供应链安全代理 API
        │ 增量分页
        ▼
本地 MySQL 镜像（hanli.env）
        │
server.py ── /dashboard /ledger /spu /baihuo /purchase /contract /status
           （`/chat` `/workbench` `/exchange` 重定向到 `/status`）
        │
   页面 / 定时任务 ──────── 不经 LLM
   对话：钉钉 Stream（网页 `/chat` 已隐藏）
        │
   Agent Core（工具注册表 + pending_action + 审计）
        │
   镜像只读查询 · 合同 · 预测 · 换货 Digital Worker · 钉钉 Outbox
```

页面、Agent 工具、钉钉催办共用 `source_cache()` 和同一套口径。Agent **不另开数据源**，也 **不直连聚水潭 OpenAPI**。读只打本地镜像；写 ERP 只有 Digital Worker 这一条。

平台定位：Agent 是自然语言控制面，Web 是结构化工作台，钉钉是协同入口，确定性工作流是执行核心，镜像库是事实来源。

员工主入口不是聊天：

| 要做的事 | 走哪 |
|---|---|
| 看进度、导出、筛采购员 | `/dashboard` `/ledger` |
| 出合同 | `/contract`（不经模型） |
| 换鞋垫 | 钉钉查询并回复「确认」后写入（网页入口已隐藏） |
| 每天催逾期 | 钉钉单聊已绑定采购员，定时，不经模型 |
| 看待确认 / 品控待办 / 运行状态 | `/status`（工作台） |
| 临时问一句、群里确认 | 钉钉 |

## 2. 数据链路

```text
供应链安全代理 API（订单 / 采购单 / 可选图片）
        │ 增量分页，modified 水位 + 5 分钟重叠
        ▼
本地 MySQL 镜像（hanli.env，可写）
        │ po_id / o_id / io_id 关联主表 + SKU 明细表
        │ 采购入库 realtime_purchase_inbounds（准交率用 io_date）
        │ 库存 / 出库 / 售后 realtime_inventory · realtime_sales_outbounds · realtime_sales_returns（60 秒增量；失败不拖垮采购/订单）
        │ 鞋服总表结果 spu_style_snapshot / 自营百货 baihuo_style_snapshot（出表时写入，不进 60 秒同步）
        │ std.samr.gov.cn 国标目录 → gb_standards
        ▼
server.py ── /api/dashboard · /api/delivery · /api/contracts/*
```

- `realtime_mirror.py`：经安全代理分页同步，幂等写入规范化业务表。
- `gb_standards.py`：国标目录元数据进 `gb_standards`，不经供应链代理。
- `database.py`：读 `hanli.env`，按 `po_id` 关联采购主表与明细；默认本年度 1 月 1 日至今。
- `procurement_data.py`：中文列名与位置数组 payload；前端只在 `frontend/src/data/payload.ts` 解码。
- 实时库连不上就报错，**不回退旧库**。
- 看板/台账热路径：进程内 `source_cache` 新鲜 30 秒，过期后 10 分钟内先返回上一份再后台重算。`PageCacheKeeper` 启动约 20 秒后预热本年，之后只在快过期时重算，进页尽量打中内存。前端同会话 25 秒内不重拉。不引入 Redis，也不把过期看板当实时数据写进 localStorage。

接口字段见 [`接口参考.md`](接口参考.md)。供应链 `orders/search` 的 `status` **不含淘系和拼多多**，不能当 ERP 全量异常池。

### 2.1 本机供应商与映射（不上库）

合同供方**不读**镜像 `realtime_suppliers`。

| 文件 | 谁维护 | 干什么 |
|---|---|---|
| `files/config/供应商管理.xlsx` | ERP 导出后覆盖 | 供应商主数据。简称匹配 ERP `seller`。合同补全称、地址、联系人、票种税率、收款账户（冻结或缺字段则中止）；看板建采购单用同一份补编号、票种、税率，并可下拉选择。gitignored |
| `files/config/contract_mappings.json` | 仓库里改 | 发票类型原文 → 票种；付款条款；ERP 付款方式 → 默认预选 |
| `files/config/internal_suppliers.json` | 仓库里改 | 内部户。不列收付款 |
| `files/config/suppliers.json` | 测试夹具 | 没有 Excel 时才回退 |

路径可用 `SUPPLIER_MASTER_XLSX` 覆盖。服务按文件修改时间重读。

### 2.2 商品图片

权威 URL 在镜像 `realtime_products`（`items.query` 的 `pic` / `pic_big`）。采购接口本身没有图片键。合同找本地文件：

1. `files/config/products.json` 的 `image_path`（手工覆盖优先）
2. `files/config/product-images/<SKU|款式>`
3. `files/data/product-images/`（同步缓存，与 ERP Worker 共用）

`resolve_product_image()` 返回本地绝对路径；都没有则合同照常生成，图位写「暂无图片」。openpyxl 只接受本地文件（webp 先转 png）。

实测口径（会变，只说明结构，不要当当前库存数字）：采购接口 0 图；订单侧有图的 SKU 远少于采购 SKU 空间，所以只采购过、近期没出单的款经常没图。图散在十几个平台 CDN，只有聚水潭 OSS 方便缩略。**原图全量进 MySQL 不可行**（体积会把看板查询挤出缓存）。以后若入库，只存小图一档、资料与二进制分表；现在继续 URL + 本地缓存。

### 2.3 采购合同

`contracts.py` 读 ERP 单头/明细，合并本机供应商表和 `products.json`，`contract_workbook.py` 写出公式驱动的 Excel。票种只有 `no_invoice` / `normal_invoice` / `special_invoice`。缺配置必须停止，不生成占位合同。**单价永不从商品主数据兜底。** 银行账号由生成器从本机 Excel 写入，不靠浏览器 options。

执行标准（`GB/T …`）来自 `gb_standards`，按明细 `poi_id` 写入 `contract_line_gb`。未选标准仍可出合同；填了废止或不存在的标准号则中止。

## 3. Agent Core

模型只理解意图、补参、选工具、组织话术。查库、计算、出文件、权限、ERP 写入、通知全部走普通代码。不绑 Agent 框架，供应商保持 `openai_compatible`。

五种概念必须分开，不能互相替代：

| 概念 | 存在哪 | 能不能当记忆 |
|---|---|---|
| 会话历史 | `agent_messages` | 否，原始日志 |
| 当前上下文 | `context_messages` 当次投影 | 否 |
| 会话摘要 | `agent_session_summaries`，默认关 | 压缩历史，必须消毒 |
| 操作员记忆 | `operator_memories`，按 `user_id` | 跨会话稳定偏好 |
| 业务状态 | 镜像库 / pending / jobs / 换货 | **绝对不能**靠记忆推断 |

发给模型的内容必须能从日志重建（事实日志 ≠ 模型可见面）。UI 回放看原文；模型上下文是派生投影。

```text
backend/agent/
  tools.py      注册表：名称 + JSON Schema + 风险级 + handler
  runner.py     工具循环，上限 AGENT_MAX_TOOL_STEPS
  router.py     意图：命令 → 抽槽 → 拒答/追问/已注册工具 → 才进 LLM
  actions.py    pending_action 确认状态机
  sessions.py   会话、上下文预算、摘要（默认关）
  store.py      SQLite 连接与建表（迁 MySQL 只换这一层）
  audit.py      运行 / 工具 / 通知
  jobs.py       进程内队列；running 300 秒租约
  outbox.py     出站投递，失败可补发
```

`AGENT_ENABLED=false` 时对话接口 503。未配 `AGENT_API_TOKEN` 时，已绑定的网页会话仍可对话；预测接口 503。看板和合同页面须登录。

新能力继续 `registry.register`，不引入插件发现、不让模型注册工具。`RESERVED_TOOLS` 只留 `supplier_scorecard`。Tool 上的 `domain` / `concurrency_mode`、`MemoryStore` / `RetrievalRouter` 是预留接口，无消费者。

### 3.1 风险与确认

| 级别 | 动作 | 要求 |
|---|---|---|
| L0 | 只读查询 | 直接执行 |
| L1 | 生成产物（合同、品控关闭） | 预览 → pending → 发起人确认 |
| L2 | 对外动作（催办、鞋垫写 ERP） | 预览冻结参数 → 确认 → 幂等执行 |
| L3 | 改主数据 | 本期不开放 |

L1/L2 **一律不直接执行**。确认人必须是发起人。不按金额或「模型历史准确率」自动放行。并发确认只有一个拿到执行权。预览参数与确认参数不一致直接拒绝。鞋垫、催办的清单在预览时冻结，确认后不重查。拒绝时工具返回结构化 `permission`，不靠 prompt 拦。

网页和钉钉走同一套确认。员工可回「确认」或「确认 编号」。幂等两层：钉钉 `message_id` 去重；执行用 `pending_action_id`。

### 3.2 意图路由

`route_message` **不查权限**。顺序：会话命令 → 实体/关键词 → 已注册工具或拒答/追问 → 未识别才进 LLM。当前话题里若只有一个采购单号 / `o_id` / SKU，缺槽用它补，不猜新编号。两个及以上先列出候选。禁止在路由里猜 `o_id` 或改工具数字。

鞋垫查询/处理是固定意图，不经 LLM。正式建单、询价、改地址、超卖直接拒答。

黄金原话在 `tests/fixtures/golden_dialogues.json`，每个已落地场景要有 **正常 / 省略 / 模糊 / 错误 / 相邻干扰**。新增 L1/L2 必须走完整确认流。最低要盖住：

1. 纯数字采购单 → `get_purchase_order`
2. 「我名下逾期」→ `delivery_reminders`（buyer + overdue）
3. 出合同但供应商未维护 → 工具报错，不编造
4. 「把 A 换成 B」没说 `o_id` → 先按待发货+源 SKU 查单，不直接 dry-run
5. 「异常订单」给了源/目标 SKU → 走换货不是催办；没给 SKU 追问类型
6. 备注 / 超卖 / 地址 → 说明第一期做不了
7. 催办发送 → 只登记 L2 pending，话术不得声称已经发出

### 3.3 工具结果信封

L0 进模型：`ok / summary / data / truncated / hint`。数字只来自 handler，模型只许引用不许重算。列表默认 `_limit` 20、封顶 200。明细超过约 30 行只留 SKU / 数量 / 待入库 / 交期。超长丢掉 `data` 只留 `summary`。截断后必须是合法 JSON。审计过长时改成带 `truncated/sha256` 的合法对象，禁止截断半截字符串。工具描述按「给初级同事」写清何时用、何时不用。

### 3.4 会话与上下文

会话键：钉钉 `conversation_id:sender_id`；逻辑上是 `tenant + channel + conversation + sender + epoch`。网页 sender 来自 `webToken`，不是客户端自报姓名。

不要用纯群共享模型上下文：指代和权限会串、私人查询会漏进群、一人补参会被另一人打断。多人协作靠共享业务对象（`quality_issue_id` / `exchange_job_id` / `pending_action_id` / `po_id` / `o_id`），每次从业务库读最新状态。

空闲超过 `AGENT_SESSION_IDLE_MINUTES`（建议 120）自动 `epoch += 1`。「新话题 / 重置」只加 epoch，不删审计。pending、品控、换货任务不随会话重置消失。同会话串行；忙时回「上一条还在处理」。

每次发给模型：系统规则 → 身份/渠道/角色 → 记忆（≤500 字，默认关）→ 摘要（≤800 字，默认关）→ 当前业务对象快照（只含单号 / `o_id` / SKU / 待确认编号）→ 近讯 → 本轮工具。

```bash
AGENT_CONTEXT_CHAR_BUDGET=60000
AGENT_TOOL_RESULT_LIMIT=8000
AGENT_SUMMARY_ENABLED=false
AGENT_SUMMARY_TRIGGER_MESSAGES=40
AGENT_MEMORY_ENABLED=false
```

摘要只留单号、SKU、供应商、已确认结论、未完成事项。金额、数量、日期、交期、状态必须重查。当前鞋垫/催办/合同/品控都是短闭环，工作集已有单号，摘要默认关；真要开也不宜以 system 角色注入。

记忆只允许：员工说「记住 / 忘记」、管理员配置、经确认的提炼。禁止 Agent 自己认为重要就永久写入。只绑定员工可积累；每人最多 20 条，每次注入最近 5 条；单条 ≤120 字；注入前扫控制字符和注入句。项目规则、风险分级、供应商映射、业务口径不允许被记忆覆盖。

### 3.5 Agent 业务库（SQLite）

默认 `AGENT_DATABASE_PATH` → `files/data/agent.sqlite3`。表名集中在 `store.py`。会话、运行、工具调用、待确认、users、staff_bindings、jobs、outbox、品控、绑定申请、网页会话、`forecast_runs`、`exchange_jobs`。迁 MySQL 是专用机器之后、只换 `store.py`。

## 4. 身份

`users.user_id`（`usr_` + 10 hex）是内部永久身份。原因：外部姓名和钉钉 userId 会变，审计、确认、记忆、ERP 命令必须长期稳定。`staff_bindings` 是兼容层：姓名 ↔ 钉钉 userId ↔ `user_id`。`operator` 自由文本保留，不删。不得静默建用户。

解析顺序：bindings 上已回填的 `user_id` → `users` 按钉钉 / 采购员别名 → 回退钉钉 id / `staff:<姓名>` / `cli:<姓名>`。旧审计里可能仍是钉钉 id。

自动合并：标准化后同一字符串、无序括号对、唯一外名、已确认花名（利特 = 李佳冬（利特）；三三 = 鞋子理单（三三）；韩立 = ERP「管理员」）。数字后缀、工号、临时工、仓前缀不自动合并，也**不要**入 `users`（`DEFERRED_ALIAS_REVIEWS`，2026-08-19 明确不要）。

管理员只认**已绑定**且 `role=admin` 的钉钉 userId。显示名和 `DINGTALK_ADMIN_USER_IDS` 不提权。韩立与其他管理员权限相同，只有韩立能「设置管理员 / 取消管理员」。

网页：钉钉绑定同意后私信花名+密码；已绑定由管理员「补发网页账号」。忘记密码再发「绑定网页」。页面登录换 `webToken`，会话 30 天。未登录不能进面板，看板/合同接口也要这份会话。页面不再填共享 Token。预测接口仍要 `AGENT_API_TOKEN`。

种子：`scripts/seed_users.py`（默认只写 `docs/reports/user_identity_analysis.md`；`--seed` 才写入 SQLite）。不做通讯录同步、不做手机号反查。SSO / OAuth / 完整 RBAC 后置。

`RequestContext` 现有 `user_id` / `channel` / `role` / `buyer_names`；预留 `tenant_id` / `roles` / `permissions` / `data_scope`，避免以后改所有 handler 签名。viewer 只能 L0。E4 权限表后置。

## 5. 钉钉

一个企业内部应用机器人，多个入口和策略域，不按催单/查询/品控/换货各复制一个机器人。Stream 长连，不需要公网回调。`DINGTALK_ENABLED` 是总闸；`DINGTALK_REMINDER_ENABLED` 另管每日催办。

| 入口 | 做什么 | 不做什么 |
|---|---|---|
| 员工私聊 | 收催办；确认/取消自己的待办 | 查询、换鞋垫、品控、当场绑定 |
| 管理员私聊 | 全部能力；「同意绑定 / 确认绑定」 | 有待办时裸「确认」先执行待办 |
| 采购协同群 | 查询、换鞋垫、品控、绑定申请、日报 | 直接改 ERP |
| 异常处置群（S4） | 换货 dry-run、受控执行 | 未绑定写操作 |
| 可选品控群（S4） | 品控台账 | 合同、换货 |

含单价或个人范围的查询默认私聊；群内按策略限制字段和行数。大结果给摘要和页面链接。

绑定：群里「绑定 姓名」→ 管理员私信 → 回「同意绑定 / 确认绑定」。姓名已被别人占用则拒绝覆盖。两个管理员同时批，先 decide 的生效。同意后群里「绑定成功」并 @ 申请人。

催办：跟单三档（≤10 天 / ≤3 天 / 已逾期），按人拆开只私聊已绑定员工。Agent 催办预览冻结清单和收件人。未绑定不发群。品控：正则直登；自然语言抽取走 L1；同一 `message_id` 不重复登记。

出站走 Outbox，失败由 JobWorker 补发（at-least-once，可能重复）。合同文件只发有时效的下载地址，不暴露服务器路径。

多群路由后置：一张 `dingtalk_routes`（scene → conversation_id、allowed_tools、可见范围），不要为了拆上下文去加第二个机器人。只有内外隔离、不同企业凭证、读写账号必须物理分开、或独立故障域时才拆机器人。多个头像不算隔离。

## 6. 换货与鞋垫

两类异常不要混：采购逾期走催办；要改 SKU 才能履约走换货。第一期只做 SKU 换货，不做备注/超卖/改地址。不准模型自造规则。

三种替换（换货页已有）：

1. 同款换规格（源、目标 `i_id` 相同）
2. 指定源 → 目标（默认仍校验同款）
3. 白名单跨款（目前 `XZ25401308-101` 那组）

对话里说「异常订单」：有源/目标 SKU 就按待发货含该 SKU 收明确 `o_id` 再登记 dry-run；没给 SKU 就追问上面哪一种。确认和执行必须落在这份 `o_id` 清单上，不允许「大概换一批」。跨款或大批量以后可加第二审批人，不靠群里一句「同意」。

普通换货：`/api/exchange/*` 仍可登记 dry-run，网页入口已隐藏。规则模型 `direct` / `map` / `map_table`。油猴不再领取。鞋垫只走钉钉确认写入。

鞋垫：钉钉固定意图 `locate_insole_orders` / `process_insole_orders`。人确认后后端串行写入；先回「已开始」，写完发【任务完成】。半码舍去小数。确认后不重扫全库。同页最多 3 路 ChangeItem。写前用列表缓存快照；写后只刷新改过的单（`_ACP` 异步最多 5 路）；对不上不记成功。已是目标 SKU 则跳过。证据落 `files/data/erp-evidence/`。结果未知不重试。审计至少含：员工 `user_id`、工具、AI 账号、命令、前后状态、时间、结果。定位按源 SKU 收单号再过滤单头，`o_id` 直接走索引不 CAST；清单 60 秒缓存，服务启动预热，过期先回上一份。钉钉 Stream 先 ACK；慢查询先回「正在查」，再后台出结果。

抖音鞋垫定时（`DouyinInsoleScheduler`）是工作流，不经 `pending_action`：09:30–18:30 每小时一轮，只处理抖音；【开始执行】和总结只发群，不私聊。已跑档位写入 `files/data/insole_schedule_state.json`，重启从文件和已发通知收回，不重播空跑。有人工待确认时空跑文案写「本轮不抢」。群里「手动跑抖音鞋垫」立刻再跑。ERP 占用时跳过本轮。人工「查询 + 确认」仍走 L2。

ERP 登录态随 `server.py` 启停，cookie 落 `files/data/secrets/erp-ai-state.json`（过渡形态，不是通用 Browser Agent）。禁止 `open_browser` / `click_anything` / `execute_js`。`ERP_AI_ENABLED` 是总闸。其他出库仍关。看板建采购单：`/purchase` 二次确认后走 `erp.create_purchase_order`（打开 `editor.aspx` 调页面 `_ACP('Confirm')`）。页面只选采购年月日，写入 `#po_date` 时带上确认当下的时分秒，让聚水潭按落单时间建字段。采购员下拉来自镜像库出现过的署名（登录花名若没有则补一行）。税率随合同票种预选（不开票/普票 0、专票 13，可改）。供应商编号 / 票种与合同共用本机供应商管理表。付款下拉与合同同一套（`contract_mappings.json` 的 3/7、发货前付款、到仓后付款、月度结算）；预选仍优先最近采购对上的 ERP 方式或这家上次写进合同的条款，写入聚水潭时再映射回 `CurrentSettlement` / `CashOnDelivery` / `MonthlyStatement`。鞋服/百货看板供应商单独一列（最近一笔采购简称），可筛选。鞋服建单明细按款式编码列出全部商品编码，数量和备注参考上次采购，没填数量的行不写入。

异常判定：`lower(status) == "question"`。不要用页面中文或 `question_desc` 模糊匹配。页面上的条数是实时数字，不能写入记忆或配置。

| Agent 分类 | 条件 | 处置 |
|---|---|---|
| 已有换货单 | `Question` 且 `type` 含「换货订单」 | 只跟踪，不再建任务 |
| 高置信待换 | `Question` 且 `question_type=线上换了商品` | 读当前 SKU，逐单 dry-run |
| 库存替换 | `Question` 且类型为缺货/淘汰品 | 必须先有目标 SKU 或白名单 |
| 人工看 | `question_type=修改订单` | 不自动当换单 |
| 其它异常 | 其余 `Question` | 不按换货处理 |

「线上换了商品」= 线上换商品、线下终止发货，通常还不是已生成的换货单。「等待售后收货」镜像样本多为已有换货单（带 `link_o_id` / `as_id`）。镜像是近期窗口，条数可以少于 ERP 实页，两者不矛盾。`question_type` / `link_o_id` / `as_id` 提升为可查字段、候选工具加 `status` / `abnormal_class` 仍是代办。

## 7. 部署与配置

第一阶段单进程多线程：HTTP、钉钉 Stream、Job/Worker。Stream 先 ACK 再后台回消息，慢查询先回进度，鞋垫定位 60 秒缓存并预热。训练离线跑，服务只读工件。`/api/health` 用 `SELECT 1` + 同步状态，不做明细 `COUNT(*)`。`health_watch.py` 每 5 分钟拉一次，异常发钉钉。先跑内网常开台式机，配置全走 `.env`，Stream 不需要公网回调。防火墙只放办公网段。

LLM：缺省 `openai_compatible`；`AGENT_PROVIDER=codex_oauth` 复用本机 Codex 登录。钉钉要 `dingtalk-stream` + AppKey/Secret。凭证在 `.gitignore`，仓库只留 `*.example`。

## 8. 已定方向与调研吸收

- 实时 ERP 数字禁止 RAG；制度/SOP/历史附件以后可以 RAG。本轮只留 `RetrievalRouter` 空壳，不部署向量库 / Neo4j。
- 模型不写 ERP、不生成页面脚本。写入必须类型化命令 + 确认 + 回读。
- 第一阶段单仓库、SQLite、单进程。
- 采购草稿、价格盯盘、库存预警已取消。

从 Hermes / Grok Build / DeepSeek Harness / Memory 调研**只吸收边界，不换框架**：

| 吸收 | 不引入 |
|---|---|
| 先处理确定性命令，再进模型循环 | LangGraph / Cordis / Grok Runtime / 通用 Computer Use |
| 显式记住/忘记、上限、注入扫描 | Agent 自己改长期记忆、Mem0 自动抽取、Letta 自画像 |
| 摘要是投影不是事实 | 生产向量库、Kafka、Celery、Graphiti |
| 工具选与执行分开；L1/L2 必须确认 | 动态发现 ERP 对象、模型注册工具、自主 Skill |
| 一个 Gateway、多入口 | 为催办/换货/询价各复制一套 Agent Loop |
| Session Event 思想（消息+审计已能追责） | 本轮重写 event-sourced 表 |

预测需求、F0 / F0.1 公式语义、ERP 对照和怎么换模型见 [`预测.md`](预测.md)。
