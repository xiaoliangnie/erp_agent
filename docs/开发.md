## 1. 原则

1. **薄 Agent + 确定性工具。** LLM 只理解意图、补齐参数、选工具、组织回答。查库、计算、生成文件、权限、ERP 写入、通知全部走普通代码。
2. **能写成固定步骤的不要做成开放 Agent。** 看板、台账、合同、催办、换货执行走页面或定时任务；对话只覆盖路径不确定的问句。
3. **实时业务数字禁止 RAG。** 库存、交期、付款、订单状态必须 Exact Query。RAG 只留给 SOP / 制度 / 历史资料，且验证后再做。
4. **缺数据就停。** 合同、订货建议、预测都不用 0 或占位信息兜底。
5. **数字忠实。** Agent 不得改、补、猜工具返回的数字。预测 ≠ 采购建议 ≠ 下单。
6. **高风险必须闭环。** 影响分析 → 预览 → 确认/审批 → 执行 → 回读核验。L1/L2 谁发起谁确认，不按金额自动放行。
7. **身份跟员工走。** Web 和钉钉落到同一个 `user_id`。共享 Token 只做传输鉴权，不代表操作员。
8. **不让模型写 ERP、不让模型开浏览器。** Playwright 只做类型化命令的 Provider。
9. **第一阶段继续单仓库、单应用库（SQLite）、单进程多线程。** 迁 MySQL / 拆进程是专用机器之后的事。
10. **增量演进，不重写。** 新能力用 Adapter 接现有 `tools.py` / `pending_actions` / 镜像库。

## 16. Agent 完成度

> **改能力必须改本节。** 完成、部分完成、新增、取消或明确不做某一项时，同步改：条目状态、百分比、分组小计、文首总进度、文末「最近变更」。
> 口径与执行顺序仍以仓库根 README.md 和本文前面章节为准；这里只回答「Agent 现在到哪了」。

| 项 | 值 |
|---|---|
| 统计日 | 2026-08-18 |

| 算法 | 计入「完成 / 部分 / 骨架 / 未做」；「不做」不进分母。条目等权，再按分组加权（见下） |

**怎么改进度**

1. 在对应分组表改该行的状态和 `%`。
2. 重算该分组小计（组内条目等权平均，四舍五入到整数）。
3. 按本节总览权重重算总进度。
4. 在「最近变更」加一行：日期、条目、从 → 到、原因。
5. 新增能力先加一行再标状态，不要只改总进度。

状态：`完成` 已闭环可用 · `部分` 主路径能用但仍有缺口 · `骨架` 代码在、默认关或缺数据 · `未做` · `不做` 本期不做（不扣分）
