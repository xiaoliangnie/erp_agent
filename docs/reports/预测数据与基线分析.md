## 1. 先说结论

1. **链路通了，模型不能用。** 代理能拉销售出库，质量 / 回测 / `k_H` 报告都出来了。仓库里的 `BaselineForecaster`（移动平均 + 星期因子）在这份数据上 WAPE 73%，不能接线上，也不能当员工采购量。
2. **所谓「365 天」有效历史大约 7 个月。** 导出窗口是 2025-08-18～2026-08-18，日汇总实际只有 **2026-01-08～2026-08-18**。去年下半年窗口按 `modified` 拉、不加状态过滤也是空页。
3. **需求极稀疏。** 1.1 万 SKU、34 万有货日，活跃期内补 0 约 70 万天。很多 SKU 在首末次出库之间只卖过几天。Baseline 会把「偶尔出一票」当成平稳日销，必然高估日常、低估爆发。
4. **负净出库是 0。** F0 定义销量 = 出库 − 可售退货。这份 CSV 里看不到退货把某天打成负数。已拍板「目前先这样」：标签先按**出库**用，不改导出、不重训。正式净销以后单独开闸。
5. **正式订货建议还缺库存、待发、`ruleType`、交期 ETA。** 没这些只能报预测曲线，不能报「该买多少」。

不要做的：不要把这次 Baseline 训进 `FORECAST_MODEL_DIR`；不要按 2025 空窗再训一版假基线；不要用 ERP 智能采购建议页的数当标签。

## 3. 有效历史：为什么不是 365 天

导出声明窗口：

```text
modified 2025-08-18 17:44:51  ~  2026-08-18 17:44:51
页数 11242    明细 1,863,714    全部 Confirmed    SKU 11,044
```

日汇总按 **`io_date`**（出库日）聚合后：

| 月 | 有货日行数（SKU×日） |
|---|---:|
| 2025-08 ~ 2025-12 | **0** |
| 2026-01 | 36,011 |
| 2026-02 | 31,587 |
| 2026-03 | 43,598 |
| 2026-04 | 49,609 |
| 2026-05 | 52,756 |
| 2026-06 | 50,594 |
| 2026-07 | 48,736 |
| 2026-08（到 18 日） | 27,886 |
| **合计** | **340,777** |
| 最早 / 最晚出库日 | **2026-01-08 / 2026-08-18** |

`quality.json` 里的有效期写成 2026-01-13～2026-08-18，是质量模块按系列首末次再收了一截；CSV 里 1 月 8 日起已有行。差几天，不影响「只有约 7 个月」。

回测因此只有三个原点：**2026-07-20、07-27、08-03**。30 天 `k_H` 样本为 0，校准表出不来。不是脚本少跑，是历史不够长。

### 3.1 2025 下半年空窗：不是 Confirmed 滤掉的

2026-08-19 用同一 Client 探了一页（只记条数和状态名，不落单据）：

| `modified` 窗口 | 过滤 | 结果 |
|---|---|---|
| 2025-09-01～09-04 | `Confirmed` | 0 页 |
| 2025-09-01～09-04 | **不限状态** | 0 页 |
| 2025-12-01～12-04 | `Confirmed` | 0 页 |
| 2025-12-01～12-04 | **不限状态** | 0 页 |
| 2026-01-10～01-13 | `Confirmed` | 有单，`io_date` 在 2026-01-10 |
| 2026-01-10～01-13 | 不限状态 | 有单，样本里出现 `Delete` |

含义：

- 空窗**不是**「只收了 Confirmed、把去年的 WaitConfirm 扔掉了」。不加状态也没有去年 9 月、12 月的出库单。
- 186 万行 Confirmed 明细里，**没有任何 `io_date` 落在 2025**。即便有「去年出库、今年才改过」的单，也会带着 2025 的 `io_date` 出现在日汇总里，实际上没有。
- 更像是：**这个开放接口凭证能看到的出库，从 2026-01 才开始**；或者 2025 的出库不在当前仓库 / 店铺授权范围，或接口不返回那么早的单。

要最终定性，只能在 ERP「销售出库」页手查 2025-09 是否真有单。有单而接口为空 → 权限或范围问题，再考虑换条件或申请。没有单 → 业务上就是 2026 年起跳，模型历史按 7 个月做，不要补假零。

## 4. 稀疏：为什么 Baseline 一定差

质量报告（`quality.json`）：

| 指标 | 值 |
|---|---|
| SKU 数 | 11,044 |
| 有货日（SKU×日） | 340,777 |
| 活跃期内补 0 的天数 | 703,896 |
| 活跃日历天数 | 1,044,673 |
| 全量件数（出库 qty 合计） | 3,574,201 |

补 0 规则（F0.1 已冻结）：只在该 SKU **首次出库日～末次出库日**之间把没卖的天补 0；窗外不补，也不拿全局均值填未见过的 SKU。

报告里抽到的活跃窗口很典型：一个 SKU 跨 100～200 个日历日，真正出库只有 3～7 天。对 Baseline 来说：

- 日均被「大量 0 + 偶尔一票」拉成很小的正数；
- 星期因子不稳定（很多星期根本没观测）；
- 爆发日会严重低估，平常日会「每天都预测出一点」。

这不是调参能救的。下一模型必须能处理**间歇需求**（间歇 Croston / 分位回归 / 按销量分层的树模型），并且评价时按销量等级拆开，不能只看一个总 WAPE。

## 5. 负净出库 = 0（已拍板：先保持）

| 项 | 值 |
|---|---|
| 负值天数 | 0 |
| 负值数量 | 0 |
| 质量模块决策 | `clip`（即便有负也按日截成 ≥0） |

F0 写的是「出库 − 可售退货」。当前导出**只拉了销售出库**，没有另拉退货单去减。负值为 0 有两种可能：

1. 这段时间可售退货很少，或退货不走这个接口；
2. 标签其实是「出库」不是「净销」，后面公式会偏高。

2026-08-19 已拍板：**目前先这样。** 不改导出脚本、不重拉、不把 Baseline 当净销模型。以后要正式净销，再单独加退货源并对一两个 SKU 的 ERP 出库/退货。在那之前，对外不要写「净销预测」，写「出库预测」。

## 6. 回测：数字怎么读

`backtest.json`，horizon 15 天，三个原点，67,445 个点：

| 指标 | 值 | 怎么读 |
|---|---|---|
| WAPE | **0.732** | 绝对误差合计 ÷ 实际合计，错大约七成 |
| Bias | **−2.05** | 平均每天每个点低估约 2 件（整体偏保守） |
| MAE | 7.01 | 有极端值，和稀疏一致 |
| p10 覆盖 | 0.969 | 下限太宽，几乎总能包住 |
| p90 覆盖 | **0.733** | 上限偏窄，约 27% 的天实际高于 p90 |
| 区间覆盖 | 0.701 | `[p10, p90]` 只罩住 70% |

过线经验（`预测.md`）：p90 覆盖应接近名义 90%。现在 73%，区间不能当安全库存。WAPE 73% 也不能指导订货。

`calibration.json`：

| 窗口 | 样本 | 误差 σ | 模型 σ | `k_H` |
|---|---:|---:|---:|---|
| 7 天 | 1,423 | 169 | 30 | **5.0（上限）** |
| 15 天 | 967 | 345 | 58 | **5.0（上限）** |
| 30 天 | **0** | — | — | **null** |

`k_H` 顶格的意思：实际累计误差大约是模型自己报的 σ 的 5 倍以上。未校准不得进安全库存，更不能进员工建议。30 天校准要等历史再长一截，或改回测原点策略（现在被 7 个月历史卡住）。

对照 ERP「预测日均 × 采购周期」的旁路（`compare.py`）只记录、不改公式。不要拿页面「建议/本次采购数」当对错标准。

## 7. 和正式订货还差什么

F0.1 要的输入 vs 现在：

| 输入 | 用途 | 现状 |
|---|---|---|
| 销售出库 | 训练 | CSV 在仓库外；**镜像无表** |
| 现势库存 | 建议量；缺则报错 | 未接入 |
| 订单待发 + 承诺发货日 | 先销后采；提前采购下界 | 未接入 |
| 在途 + ETA | 只有 ETA 早于需求日的在途能抵 | 数量−已入库有；**无入库日 / 无 ETA 筛选** |
| SKU `ruleType` | 先销后采 vs 提前采购 | 未接入（页面上有，没进库） |
| SKU/供应商交期 | `coverage_days` | 只有系统默认 15 天 |

现服务 `order_suggestion` 仍是旧公式：内部自己 `predict()`、在途未筛 ETA、没有待发、没有 `k_H`。旁路公式在 `backend/forecast/replenish.py`，**没接线上**。

没有库存快照：可以报预测曲线，**不能**报正式采购量。这点和合同「缺单价就停」同一哲学。

入库单镜像（准交率 A1）一旦建起来，在途 ETA 会好做一些，但库存 / 待发 / 规则仍是另三道闸。
