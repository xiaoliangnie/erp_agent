# User Identity 设计说明

> **归档。** 现行说明见 [`../../架构.md`](../../架构.md) 身份一节。

> 2026-08-17。实现以代码为准：`backend/agent/users.py`、`backend/staff_names.py`、`backend/agent/context.py`。

## 目标

内部 `user_id` 稳定。ERP 采购员、网页署名、钉钉员工最终指向同一人。本轮只做 User 基础，不做企业 IAM。

## 表

Agent SQLite `users`（不是镜像库）：

| 字段 | 说明 |
|---|---|
| user_id | `usr_` + 10 hex，永久 |
| real_name / nickname / canonical_name / display_name | 展示与标准名 |
| erp_buyer_aliases_json | 已确认的 ERP 采购员写法 |
| dingtalk_userid / dingtalk_unionid | 预留；绑定后回填 userid |
| mobile / department / status / source | 预留或种子来源 |

`staff_bindings.user_id` 可空，seed / 绑定后回填。

## 归一化

`normalize_staff_name()`：NFKC、括号、空白。

自动合并：

- 标准化后同一字符串
- 同一无序括号对（`张三（阿飞）` = `阿飞（张三）`）
- 唯一外名命中（`李佳冬` = `李佳冬（利特）`）
- 唯一花名命中，包括岗位署名（`三三` = `鞋子理单（三三）`，2026-08-17 人工确认）

不自动合并：数字后缀、括号内工号、临时工、花名对应多个人。

人工确认（`CONFIRMED_IDENTITIES`，`--seed` 时写入）：

- 2026-08-17：「三三」=「鞋子理单（三三）」
- 2026-08-17：韩立 = ERP「管理员」；钉钉绑定回填到同一 `user_id`
- 2026-08-18：韩立 / 「管理员」视为钉钉 `admin`；员工绑定需管理员私聊同意后才写入 `staff_bindings`
- 2026-08-18：管理员只认已绑定的钉钉 userId，显示名不能提权。韩立为最高管理员，可私信「设置管理员 姓名」。网页身份：已绑定员工在群里发「绑定网页」，私信 20 位码，网页填姓名+码换 `webToken`，之后不再靠客户端 `operator`
- 2026-08-18：`DINGTALK_ADMIN_USER_IDS` 不再提权。韩立与其他管理员权限相同，只有韩立能改角色。绑定审批用「同意绑定 / 确认绑定」；姓名已被占用不覆盖。冲突花名不入 `users`。不做通讯录同步和手机号反查。

其余冲突别名见 `DEFERRED_ALIAS_REVIEWS`，先不合并、不建用户。

`resolve_user_by_erp_buyer` 匹配不到不建用户；多人命中返回 `ambiguous_buyer`。

## 种子

```text
python scripts/seed_users.py
python scripts/seed_users.py --live
python scripts/seed_users.py --live --seed
```

默认只写 `docs/reports/user_identity_analysis.md`。`--seed` 才写入 Agent SQLite。

2026-08-17 已对镜像库执行 `--live --seed`：51 个自动确认用户在 `files/data/agent.sqlite3`。待确认别名没有建用户。

## 请求上下文

`RequestContext` 现有：`user_id` / `channel` / `role` / `buyer_names`。

预留：`tenant_id` / `conversation_id` / `session_id` / `roles` / `permissions` / `data_scope`（空或默认）。

## 不做

SSO、OAuth、RBAC 矩阵、店铺权限、钉钉完整绑定产品、三套人员体系。
