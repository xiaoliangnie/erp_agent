# 采购数据项目设计（第一阶段）

## 目标

把采购看板和交期提醒台账统一接到 MySQL，同时保持两个页面现有的筛选、图表、抽屉和 CSV 导出能力。浏览器永远不接触数据库账号或密码。

## 当前架构

```text
供应链安全代理 API（订单 / 采购单 / 可选图片）
        │ 增量分页，modified 水位 + 5 分钟重叠
        ▼
本地 MySQL 镜像（hanli.env，可写）
        │ po_id / o_id 关联主表 + SKU 明细表
        │ std.samr.gov.cn 国标目录 → gb_standards
        ▼
server.py ── /api/dashboard          ── React SPA /dashboard
    │     ├─ /api/delivery           ── React SPA /ledger
    │     └─ /api/contracts/generate ── React SPA /contract ── Excel
```

- `realtime_mirror.py`：通过安全代理分页同步采购单和订单，幂等写入四张规范化业务表，并记录独立成功水位。
- `gb_standards.py`：从 std.samr.gov.cn 高级检索 JSON 同步国标目录元数据到 `gb_standards`。默认同范围由 `realtime_products.category` + `files/config/gb_category_map.json` 决定，按 SAMR id 幂等，内容哈希不变则不改行；`gb_standard_families` 记录标准属于哪个商品目录族。
- `database.py`：读取 `hanli.env`，按 `po_id` 关联 `realtime_purchase_orders` 与 `realtime_purchase_order_items`；默认只查本年度 1 月 1 日至今天。
- `sync_purchase_data.py`：按需把 CSV 幂等写入显式指定的测试数据库，不参与生产运行链路。
- `server.py`：只使用实时数据库，只开放业务接口和 `frontend/dist/` 里的前端产物，不会把 env 文件或源 CSV 发布出去。
- `procurement_data.py`：统一维护字段口径和前端数据编码。
- `frontend/src/`：Vite + React + TypeScript 单页应用，五个页面是五条路由；`data/payload.ts` 是位置数组 payload 的唯一解码点。页面只走同源 API，离线快照回退已下线（旧实现留在 `legacy/`）。

## 本机供应商与映射（不上库）

合同供方**不读**镜像库 `realtime_suppliers`。三份本机文件分工不同：

| 文件 | 谁维护 | 干什么 |
|---|---|---|
| `files/config/供应商管理.xlsx` | 你从 ERP 导出后覆盖上传 | **供应商主数据**。按「简称」匹配 ERP `seller`，补全称、地址、联系人、发票类型、收款账户。同一简称多行只留创建时间最近的。冻结或缺全称/地址/电话则中止。gitignored，不进仓库 |
| `files/config/contract_mappings.json` | 仓库里改 | **映射表**，不是供应商名单。Excel「发票类型」原文 → 票种；付款方式条款；ERP `payment_method` → 默认预选哪一条 |
| `files/config/internal_suppliers.json` | 仓库里改 | 公司内部户。不列收付款，不要求 Excel 全称 |
| `files/config/suppliers.json` | 测试夹具 | **没有 Excel 时才回退**。正式环境有 Excel 就不会读它 |

路径可用 `SUPPLIER_MASTER_XLSX` 覆盖。服务按文件修改时间重读，不必重启。

## 商品图片

权威字段在镜像 `realtime_products`（`items.query` 的 URL）。合同找本地文件的顺序：

1. `files/config/products.json` 的 `image_path`
2. `files/config/product-images/<SKU|款式>`
3. `files/data/product-images/`（同步缓存）

都没有则合同照常生成，图位写「暂无图片」。原图不进 MySQL。实测覆盖率和小图入库方案见 [`archive/商品资料与图片.md`](../archive/商品资料与图片.md)。

## 采购合同生成

采购合同以 `files/templates/采购合同模板.xlsx` 为业务和视觉基准。Agent、网页和命令行共用 `backend/contracts.py`：读取 ERP 单头/明细后，按供应商简称合并本机 `files/config/供应商管理.xlsx`（`backend/supplier_master.py`，不上库），按 SKU/款号合并 `files/config/products.json`，再由 `backend/contract_workbook.py`（openpyxl）输出公式驱动的 Excel。

票种为 `no_invoice`、`normal_invoice`、`special_invoice`。员工选择后，系统同步决定税率、商品单价、单价表头和合同第 4 条；配置缺失时必须停止生成。图片解析顺序为产品映射文件、API 图片缓存和 ERP Worker 缓存。

合同明细把 **国标码**（EAN/商品条码）、**品名**、**执行标准**（`GB/T …`，来自 `gb_standards`）分成三列，执行标准紧跟品名。选项接口按商品分类对应的目录族列出现行 / 即将实施标准，不自动勾选；员工选择按采购明细 `poi_id` 写入 `contract_line_gb`，预览和下载都会保存。未选执行标准仍可生成合同；填了不存在或已废止的标准号则中止。`files/templates/采购合同模板.xlsx` 只含固定栏（需方、收货信息、包装、检验、条款），不含采购单内容。

未完项和下一阶段见 [`开发.md`](../开发.md)。分类/包装/单位改读 `realtime_products`（**单价仍不兜底**）是迁机器之后的 P2。
